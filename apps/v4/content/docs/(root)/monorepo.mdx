## はじめる

<Steps>

### 新しいモノリポジトリ プロジェクトを作成する

新しい Monorepo プロジェクトを作成するには、`--monorepo` フラグを指定して `init` コマンドを実行します。

```bash
npx shadcn@latest init --monorepo
```

次に、使用するテンプレートを選択します。

```bash
? Select a template ›
❯   Next.js
    Vite
    TanStack Start
    React Router
    Astro
```

これにより、`web` と `ui` という 2 つのワークスペースを持つ新しいモノリポジトリ プロジェクトが作成されます。
ビルド システムとして [Turborepo](https://turbo.build/repo/docs) を使用します。

すべてがセットアップされるので、プロジェクトへのコンポーネントの追加を開始できます。

### プロジェクトにコンポーネントを追加する

プロジェクトにコンポーネントを追加するには、**アプリのパス**で `add` コマンドを実行します。

```bash
cd apps/web
```

```bash
npx shadcn@latest add [COMPONENT]
```

CLI は、追加しているコンポーネントのタイプを判断し、
正しいファイルを正しいパスに移動します。

たとえば、`npx shadcn@latest add button` を実行すると、CLI は `packages/ui` の下にボタン コンポーネントをインストールし、`apps/web` 内のコンポーネントのインポート パスを更新します。

`npx shadcn@latest add login-01` を実行すると、CLI は `button`、`label`、`input`、および `card` コンポーネントを `packages/ui` にインストールし、`login-form` コンポーネントを `apps/web/components` にインストールします。

### コンポーネントのインポート

次のように、`@workspace/ui` パッケージからコンポーネントをインポートできます。

```tsx
import { Button } from "@workspace/ui/components/button"
```

`@workspace/ui` パッケージからフックとユーティリティをインポートすることもできます。

```tsx
import { useTheme } from "@workspace/ui/hooks/use-theme"
import { cn } from "@workspace/ui/lib/utils"
```

</Steps>

## ファイル構造

新しいモノリポジトリ プロジェクトを作成すると、CLI は次のファイル構造を作成します。

```txt
apps
└── web         # Your app goes here.
    ├── app
    │   └── page.tsx
    ├── components
    │   └── login-form.tsx
    ├── components.json
    └── package.json
packages
└── ui          # Your components and dependencies are installed here.
    ├── src
    │   ├── components
    │   │   └── button.tsx
    │   ├── hooks
    │   ├── lib
    │   │   └── utils.ts
    │   └── styles
    │       └── globals.css
    ├── components.json
    └── package.json
package.json
turbo.json
```

## 要件

1. すべてのワークスペースに `components.json` ファイルが必要です。 `package.json` ファイルは、依存関係をインストールする方法を npm に指示します。 `components.json` ファイルは、コンポーネントをインストールする方法と場所を CLI に指示します。

2. `components.json` ファイルは、ワークスペースのエイリアスを適切に定義する必要があります。これにより、コンポーネント、フック、ユーティリティなどをインポートする方法が CLI に指示されます。

```json showLineNumbers title="apps/web/components.json"
{
  "$schema": "https://ui.shadcn.com/schema.json",
  "style": "base-nova",
  "rsc": true,
  "tsx": true,
  "tailwind": {
    "config": "",
    "css": "../../packages/ui/src/styles/globals.css",
    "baseColor": "neutral",
    "cssVariables": true
  },
  "iconLibrary": "lucide",
  "aliases": {
    "components": "@/components",
    "hooks": "@/hooks",
    "lib": "@/lib",
    "utils": "@workspace/ui/lib/utils",
    "ui": "@workspace/ui/components"
  }
}
```

```json showLineNumbers title="packages/ui/components.json"
{
  "$schema": "https://ui.shadcn.com/schema.json",
  "style": "base-nova",
  "rsc": true,
  "tsx": true,
  "tailwind": {
    "config": "",
    "css": "src/styles/globals.css",
    "baseColor": "neutral",
    "cssVariables": true
  },
  "iconLibrary": "lucide",
  "aliases": {
    "components": "@workspace/ui/components",
    "utils": "@workspace/ui/lib/utils",
    "hooks": "@workspace/ui/hooks",
    "lib": "@workspace/ui/lib",
    "ui": "@workspace/ui/components"
  }
}
```

3. 両方の `components.json` ファイルに同じ `style`、`iconLibrary`、および `baseColor` があることを確認します。

4. **Tailwind CSS v4 の場合、`components.json` ファイル内の `tailwind` 設定を空のままにしておきます。**

これらの要件に従うことで、CLI は ui コンポーネント、ブロック、ライブラリ、フックを正しいパスにインストールし、インポートを処理できるようになります。

<Callout className="mt-6">
`package.json#imports` は、パッケージ内のパッケージローカルのエイリアスに対して適切に機能します。
ワークスペース (たとえば、`packages/ui` 内)。共有ワークスペースのインポートの場合、
`@workspace/ui/components` として、明示的なエイリアスを `components.json` に保持します。の
CLI はこれらのエイリアスを使用して、ワークスペースの境界を越えてファイルをルーティングします。
</Callout>

## `package.json#imports` の使用

パッケージインポートを使用し、依存しないモノリポジトリの場合
`tsconfig.json` `paths`、次を使用します。

- 各ワークスペース内のファイルのローカル `#...` エイリアス
- 共有インポート用のワークスペース パッケージ `exports`
`@workspace/ui/components`

たとえば、アプリのワークスペースはローカル パッケージのインポートを使用できます。

```json showLineNumbers title="apps/web/package.json"
{
  "name": "web",
  "private": true,
  "type": "module",
  "imports": {
    "#components/*": "./src/components/*.tsx",
    "#lib/*": "./src/lib/*.ts",
    "#hooks/*": "./src/hooks/*.ts"
  },
  "dependencies": {
    "@workspace/ui": "workspace:*"
  }
}
```

```json showLineNumbers title="apps/web/components.json"
{
  "aliases": {
    "components": "#components",
    "ui": "@workspace/ui/components",
    "lib": "#lib",
    "hooks": "#hooks",
    "utils": "@workspace/ui/lib/utils"
  }
}
```

また、共有 UI パッケージは、`exports` を使用してインストール ターゲットを公開できます。

```json showLineNumbers title="packages/ui/package.json"
{
  "name": "@workspace/ui",
  "private": true,
  "type": "module",
  "imports": {
    "#components/*": "./src/components/*.tsx",
    "#lib/*": "./src/lib/*.ts",
    "#hooks/*": "./src/hooks/*.ts"
  },
  "exports": {
    "./globals.css": "./src/styles/globals.css",
    "./components/*": "./src/components/*.tsx",
    "./lib/*": "./src/lib/*.ts",
    "./hooks/*": "./src/hooks/*.ts"
  }
}
```

```json showLineNumbers title="packages/ui/components.json"
{
  "aliases": {
    "components": "#components",
    "ui": "#components",
    "lib": "#lib",
    "hooks": "#hooks",
    "utils": "#lib/utils"
  }
}
```

この設定では:

- アプリから共有 UI パッケージに追加されたファイルは、経由してルーティングされます。
`@workspace/ui/...`
- `packages/ui` 内に追加されたファイルは、パッケージローカルの `#...` エイリアスを使用します。
- 共有パッケージは、別のワークスペースによって参照されるパスをエクスポートする必要があります

フレームワーク固有のパッケージ インポートの設定については、[パッケージ インポート ガイド](/docs/package-imports) を参照してください。
