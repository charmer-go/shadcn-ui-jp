### 名前空間レジストリ

3.0 の最大の変更点は、名前空間レジストリです。 `@registry/name` 形式を使用して、レジストリ (コミュニティレジストリ、会社のプライベートレジストリ、または内部レジストリ) からコンポーネントをインストールできるようになりました。

これにより、チームやプロジェクト間でコードを配布することが容易になります。

`components.json`でレジストリを構成します。

```json title="components.json"
{
  "registries": {
    "@acme": "https://acme.com/r/{name}.json",
    "@internal": {
      "url": "https://registry.company.com/{name}",
      "headers": {
        "Authorization": "Bearer ${REGISTRY_TOKEN}"
      }
    }
  }
}
```

次に、`@registry/name` 形式を使用してコンポーネントをインストールします。

```bash
npx shadcn add @acme/button @internal/auth-system
```

完全に分散化されています。中央の登録機関はありません。必要な名前空間を作成し、コンポーネントを整理しますが、チームにとっては意味があります。

```json title="components.json" showLineNumbers
{
  "registries": {
    "@design": "https://registry.company.com/create/{name}.json",
    "@engineering": "https://registry.company.com/eng/{name}.json",
    "@marketing": "https://registry.company.com/marketing/{name}.json"
  }
}
```

コンポーネントは、異なるレジストリのリソースに依存することもあります。すべてが適切なソースから自動的に解決され、インストールされます。

```json title="registry-item.json" showLineNumbers
{
  "name": "dashboard",
  "type": "registry:block",
  "registryDependencies": [
    "@shadcn/card", // From default registry
    "@v0/chart", // From v0 registry
    "@acme/data-table", // From acme registry
    "@lib/data-fetcher", // Utility library
    "@ai/analytics-prompt" // AI prompt resource
  ]
}
```

### プライベートレジストリ

コンポーネントを非公開にしておく必要がありますか?ご対応させて頂きます。ついでに、API キー、またはカスタムヘッダーを使用して認証を構成します。

```json title="components.json"
{
  "registries": {
    "@private": {
      "url": "https://registry.company.com/{name}.json",
      "headers": {
        "Authorization": "Bearer ${REGISTRY_TOKEN}"
      }
    }
  }
}
```

プライベートコンポーネントは非公開のままです。独自の UI ライブラリを備えたエンタープライズ チームに最適です。

基本認証、ベアラーに関して、API キー入力パラメータ、カスタムヘッダーなど、すべての主要な認証方法をサポートしています。

については、[認証ドキュメント](/docs/registry/authentication) を参照してください。

### 検索と発見

3 つの新しいコマンドにより、必要なものを簡単に見つけることができます。

1. インストールする前にレジストリの項目を表示する

```bash
npx shadcn view @acme/auth-system
```

2. レジストリから項目を検索する

```bash
npx shadcn search @tweakcn -q "dark"
```

3. レジストリのすべての項目をリストします。

```bash
npx shadcn list @acme
```

コンポーネントをインストールする前にプレビューします。複数のレジストリを横断して検索します。事前にコードとすべての依存関係を確認してください。

4 月に遡って、MCP サーバーの最初のバージョンを[導入](https://x.com/shadcn/status/1917597228513853603)しました。 それ以来、私たちが学んだすべてを知って、より優れた MCP サーバーを構築してきました。

新機能は次のとおりです。

- すべてのレジストリで動作します。ゼロ構成
- お気に入りのMCPクライアントに追加する 1つのコマンド
- 基盤となるツールを改善しました
- CLIおよびレジストリとの統合の向上
- 同じプロジェクト内の複数のレジストリのサポート

MCPサーバーをプロジェクトに追加します。

```bash
npx shadcn@latest mcp init
```

詳細については、[docs](/docs/mcp) を参照してください。

### すべてをより速く

レジストリ解決エンジンを最初から完全に書き直しました。より高速かつスマートで、最も扱いにくい依存関係ツリーも処理します。

- 最大 3 倍高速な依存関係の解決
- よりスマートなファイルの重複排除とマージ
- すぐに使用できるモノリポジトリのサポートの向上
- レジストリ作成者向けの `build` コマンドを更新しました

### エラー処理の改善

レジストリ開発者は、問題が発生したときにユーザー (および LLM) をガイドするためにカスタム エラー メッセージを提供できるようになりました。 CLI には、一般的な問題に対して、対処可能なエラーが表示されます。

```txt
Unknown registry "@acme". Make sure it is defined in components.json as follows:
{
  "registries": {
    "@acme": "[URL_TO_REGISTRY]"
  }
}
```

環境変数はありませんか? CLIは必要なものを正確に示します。

```txt
Registry "@private" requires the following environment variables:
  • REGISTRY_TOKEN

Set the required environment variables in your .env or .env.local file.
```

レジストリ作成者は、ユーザーや AI エージェントが問題を迅速に理解して修正できるように、応答にカスタム エラー メッセージを提供できます。

```txt
Error:
You are not authorized to access the item at http://example.com/r/component.

Message:
[Unauthorized] Your API key has expired. Renew it at https://example.com/api/renew-key.
```

### アップグレードガイド

ここが最も良い点です。ユーザーにとって重要な変更はありません。既存の `components.json` はまったく同じように機能します。インストールされているすべての要素はまったく同じように動作します。

開発者向けに、プログラム API を直接使用している場合、より良い関数を優先していくつかの関数を非推奨にしました。

- `fetchRegistry` → `getRegistry`
- `resolveRegistryTree` → `resolveRegistryItems`
- スキーマが `shadcn/registry` から `shadcn/schema` パッケージに移動しました

```diff
- import { registryItemSchema } from "shadcn/registry"
+ import { registryItemSchema } from "shadcn/schema"
```

それでおしまい。真剣に。それ以外はすべて正常に機能します。
