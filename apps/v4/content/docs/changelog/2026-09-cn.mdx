**すべての shadcn コンポーネントは、`cn` パッケージから `cn` をインポートするようになりました。**

何年もの間、すべての shadcn プロジェクトは同じ 5 行から始まりました。
`lib/utils.ts`: `clsx` をインポート、`twMerge` をインポート、一方を他方でラップし、エクスポート
`cn`としてください。それは機能しましたが、2 つの依存関係とヘルパーが必要になることを意味しました。
すべてのプロジェクトとすべてのレジストリにコピーします。

それをパッケージに移しました。 [`cn`](https://github.com/shadcn-ui/cn) は
`twMerge(clsx(...))` のドロップイン交換品。より小さく、より速く、発送可能です
同じ API なので、呼び出しサイトでは何も変わりません。

```tsx
import { cn } from "cn"

;<div className={cn("flex items-center", className)} />
```

## 何が変わったのか

- レジストリ コンポーネント、ブロック、例は、代わりに `cn` から `cn` をインポートします。
`@/lib/utils`。
- `npx shadcn init` は、`cn` をインストールし、一行の `lib/utils.ts` を生成します。
- `cn` を使用するすべてのレジストリ項目は、それを依存関係として宣言します。
`npx shadcn add` は、この変更前に作成されたプロジェクトにインストールします。

## lib/utils.ts

`utils` レジストリ項目はまだ存在します。 `cn` が再エクスポートされるようになったので、独自のコードを作成できます。
作業は継続し、プロジェクト ヘルパーのための場所は 1 か所にあります。

```ts title="lib/utils.ts"
export { cn } from "cn"
```

## 既存のプロジェクト

何も壊れません。 `lib/utils.ts` は動作し続け、新しいコンポーネントがインストールされます
その隣に`cn`。プロジェクトの残りの部分を上に移動し、`clsx` をドロップして、
`tailwind-merge`、移行を実行します。

```bash
npx shadcn@latest migrate cn
```

インポートを書き換え、`twMerge(clsx(...))` 呼び出しを置き換え、古いものを削除します。
パッケージを参照するものがなくなったとき。を参照してください。
詳細については、[CLI ドキュメント](/docs/cli#merge-cn) を参照してください。
